## ISM3232 Lab 12: Tools and Guardrails

This FAQ Assistant (`FAQAssistant`) answers general store policies and operational questions for Tampa Outfitters by using an underlying lookup tool (`FAQKnowledgeBase`). This assistant operates as a rule based prototype which utilizes keyword matching and mock data structures instead of a fully autonomous. Requests regarding financial transactions, returns, or disputes are passed directly to a human agent, as it involves sensitive information and cannot be securely handled by this bot, as well as automated keyword lookups not being able to make policy exceptions. If this system were to be connected to real customer data without safeguards, rule matching errors or unverified inputs could expose sensitive personal information or trigger unauthorized account actions. One request that the model handeled well was answering store hour questions by using the FAQ lookup tool and returning the correct information. It also handeled warranty claims well by submitting them for staff review instead of immediately approving them. The safety door refused a request when the model attempted to use a customer name that was not provided by the user, which prevents the assistant from making up random information. During development of this mini-project, I had to add instructions that required the model to only use customer names explicitly given in the conversation and to ask for missing information when appropriate. I also added instructions that warranty claims must be approved by a human staff member before they can be recorded. These changes improved the reliability and safety of Bizzy's behavior.
